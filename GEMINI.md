# Gemini AI Intelligence Layer

This document outlines the implementation of the **Gemini AI** integration and the custom **Intelligence Layer** within the Egie AI Agentic Workspace.

## 🧠 The Intelligence Layer (Phase 2)
To move beyond simple chat responses, we've implemented a robust three-stage pipeline that processes all user queries:

### 1. Planner Layer
- **Role**: Strategic Analysis.
- **Goal**: Deconstruct the user's intent and determine the complexity.
- **Logic**: It classifies the query into categories like `Direct Answer` or `Research Task`. It identifies which modules (Memory, RAG, Tools) are required.

### 2. Executor Layer
- **Role**: Operational Orchestration.
- **Goal**: Execute the plan generated by the Planner.
- **Process**:
    - Fetches relevant **Long-Term Memory** entries.
    - Performs **Knowledge Retrieval (RAG)** from the Kitab library.
    - Prepares the context-injected prompt for the LLM.
    - Handles streaming and background tasks.

### 3. Evaluator Layer (The Gatekeeper)
- **Role**: Quality Assurance.
- **Goal**: Validate the output before the user sees it.
- **Checks**:
    - **Source Verification**: Ensures claims are backed by RAG references.
    - **Consistency Check**: Compares the response with User Preferences in Memory.
    - **Hallucination Detection**: Flags ungrounded claims.
    - **Intelligence Scoring**: Heuristic scoring of Accuracy and Consistency.

## 🛠️ Implementation Details

### Model Strategy
We prioritize the **Gemini 2.5 Flash** (or latest equivalent) for its balance of speed and reasoning, with fallbacks to other frontier models to ensure high availability.

### Context Management
- **Assembled System Prompt**: Combines Identity (Murabbi), Persona, Developer Constraints, Active Memories, and RAG Context.
- **Streaming Logic**: All responses are streamed for a responsive PWA experience.
- **Agent Trace**: Each step of the Intelligence Layer is visually reported to the user in real-time.

## 🛡️ Security & Privacy
- **Server-Side API**: All Gemini API calls are made server-side (`server.ts`) to keep API keys hidden.
- **Sensitive Data Filtering**: Internal reasoning blocks (`<think>`) are stripped before final delivery to maintain a clean "Murabbi" interface.
